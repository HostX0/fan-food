# فن فود — من مطبخنا إلى لمّتكم

منيو عربي باتجاه RTL، مبني بـ Next.js App Router وReact وTypeScript، بواجهة مصممة خصيصاً لهوية فن فود. المشروع **Frontend فقط**: لا قاعدة بيانات، لا تسجيل دخول، لا بوابة دفع، ولا WhatsApp Business API.

## التشغيل

استخدم Node.js 22 LTS أو إصداراً أحدث متوافقاً، في بيئة متصلة بالإنترنت:

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`.

للفحص والبناء:

```bash
npm test
npm run typecheck
npm run build
npm start
```

`npm run build` ينتج مجلد `out/` القابل للاستضافة الثابتة. `npm start` يشغّل خادم ملفات ثابتة محلياً على المنفذ 3000؛ هذا ليس Backend للطلبات. يمكن تعديل المنفذ عبر متغير `PORT`.

لا يتطلب التطبيق مفاتيح API أو ملف أسرار. لم يُنشأ lockfile لأن تثبيت حزم الإنتاج لم يكن متاحاً في بيئة التسليم؛ أنشئه بأول تثبيت ناجح ثم اعتمده بالمستودع.

## ما تم تنفيذه

- 8 أقسام كاملة؛ 58 بطاقة صنف تضم 73 خيار حجم وسعر من آخر نسخة مقروءة من المنيو.
- اختيار الحجم والعدد، وملاحظات لكل بند؛ المعكرونة تشمل اختيار لحم أو دجاج.
- بحث يدعم اختلافات كتابة العربية والأرقام، وفرز بالأسعار، ومفضلة.
- سلة ملخص ثابتة للشاشات الكبيرة، وزر سلة سفلي للموبايل والتابلت، ومراجعة الطلب في نافذة مناسبة للجهاز.
- حفظ السلة والمفضلة محلياً بالمتصفح، مع تنظيف البيانات التالفة والتحقق من الخيارات وإعادة قراءة السعر من الكتالوج.
- بيانات الزبون، التحقق من رقم عراقي، معاينة الرسالة، نسخها، وفتح واتساب.
- تنقل بلوحة المفاتيح، حصر التركيز داخل النوافذ، إغلاق Escape، دعم تقليل الحركة، ورسائل حالة مسموعة لقارئ الشاشة.
- صور WebP محلية، تحميل مؤجل للصور غير الرئيسية، هوية خضراء وكريمية، وخطوط Cairo وManrope عبر Google Fonts مع بدائل نظامية.
- شعار مأخوذ من المرجع المعتمد، وفوتر بالنص المطلوب **By The Third Act LLC** مع رابط الوكالة.

## الطلب عبر واتساب

1. يختار الزبون الأصناف والأحجام وعدد العبوات.
2. يراجع السلة ويدخل الاسم والموبايل والمدينة والمنطقة والعنوان؛ النقطة الدالة والملاحظات اختياريتان.
3. يعاين الرسالة التي تتضمن الأصناف والأحجام والعدد وسعر الوحدة ومجموع كل بند ومجموع الأصناف وبيانات التوصيل.
4. يضغط «فتح واتساب وإرسال الطلب»، فيفتح واتساب برسالة جاهزة، ثم **يضغط إرسال داخل واتساب بنفسه**.

لا يمكن للواجهة وحدها إرسال رسالة صامتة أو معرفة أنها وصلت. لذلك لا يظهر تأكيد وهمي، ولا تُفرَّغ السلة تلقائياً عند فتح واتساب. مرجع الرسالة مجرد رمز للمراجعة، وليس حجزاً مسجلاً في قاعدة بيانات.

إذا تجاوز رابط الرسالة 7500 حرف، تعرض الواجهة نسخ الرسالة وفتح واتساب للصقها، بدلاً من الاعتماد على رابط طويل. إذا لم يُسمح بالنسخ التلقائي، تُحدّد الرسالة للنسخ اليدوي.

أجور التوصيل والإضافات غير المسعّرة ليست ضمن المجموع، ولا يتم افتراضها. المطعم يؤكد التوفّر وموعد التجهيز وأجور التوصيل والإضافات والمبلغ النهائي في المحادثة. أسعار الواجهة والرسالة قابلة للتلاعب من جهاز العميل؛ على المطعم مراجعتها، وليست آلية تسعير موثوقة على الخادم.

## التعديل والصيانة

| الملف | الغرض |
|---|---|
| `src/data/menu.json` | الأقسام والأصناف والأحجام والأسعار والصور وخيارات النوع |
| `src/data/site.ts` | رقم واتساب، إنستغرام، المدينة الافتراضية، رابط الفوتر |
| `src/app/globals.css` | ألوان الهوية، التخطيط، المقاسات، والحركات |
| `src/components/menu-app.tsx` | البحث، الكتالوج، السلة، وخطوات الطلب |
| `src/components/primitives.tsx` | نافذة الحوار، عرض السعر، والتحكم بالكمية |
| `src/lib/core.mjs` | حسابات الطلب، تنظيف السلة، والتحقق وإنشاء الرسالة |
| `src/app/layout.tsx` | اللغة، الخطوط، الميتاداتا، والأيقونات |
| `public/images/` | الصور المستخدمة في الواجهة |

أضف الصنف وأحجامه في `menu.json`. لكل صنف `id` ثابت ولكل حجم `id` ثابت و`price` رقمي صحيح بالدينار. لا تغيّر المعرّفات لمجرد تعديل الأسعار، حتى تستمر السلة المحفوظة بالعمل. عند إضافة صنف، حدّث `searchText` و`meta` واختبارات عدد عناصر الكتالوج حسب التغيير المقصود.

المكتبات: Next.js 16.3.5، React 19.3.0، Tailwind CSS 4.1.10، Font Awesome Free SVG Icons 6.7.2. الواجهة تستخدم `<dialog>` الأصلي بدلاً من اعتماد ثقيل للنوافذ، مع معالجة التركيز وEscape في التطبيق.

## الخصوصية

السلة والمفضلة فقط تُخزَّنان في localStorage. الاسم والعنوان والموبايل تُحفظ في ذاكرة الصفحة أثناء الاستخدام ولا تُكتب في التخزين الدائم. لا يوجد Analytics أو نظام تتبع أو Backend مضاف. الاتصال الخارجي المستخدم هو خطوط Google وروابط إنستغرام والوكالة وواتساب عند فتحها.

## الاختبارات وحالة التسليم

نجحت **22 حالة لاختبارات منطق الطلب**. ونجح **32 فحصاً في Chromium لمعاينة الواجهة** تشمل ثمانية مقاسات شاشة، والبحث، والأحجام، والسلة، والتحقق، والرسالة، والفوتر. التفاصيل في `docs/QA_REPORT.md`.

**حدود التحقق المهمة:** لم يتم تشغيل `npm install` أو `next build` أو فحص TypeScript الكامل على حزم الإنتاج، لأن بيئة التنفيذ لا تسمح بتنزيل npm. فحوصات الواجهة استخدمت نفس مكوّنات TSX والمنطق في حزمة معاينة محلية مستقلة مبنية بـ TypeScript ومشغلة بمكتبة React قديمة متاحة في بيئة الاختبار؛ ليست إثباتاً لبناء Next.js/React 19. المعاينة تستخدم CSS المشروع دون معالجة Tailwind، وخطاً نظامياً عندما يتعذّر تحميل Google Fonts. نسخة React القديمة **ليست ضمن مشروع الإنتاج** ولا يجب نشر حزمة المعاينة كمنتج نهائي.

لم يتم النشر على استضافة حية، ولم تُرسل رسالة طلب حقيقية، ولم تُختبر أجهزة iOS/Safari فعلية. الـManifest لا يعني وجود خدمة عمل دون اتصال؛ لا يوجد Service Worker.

## قبل النشر

نفّذ تثبيت الحزم وفحص الأنواع والبناء على جهاز متصل، ثم اختبر مجلد `out/`. راجع الأسماء والأسعار والصور والتواصل مع صاحب المطعم. اختبر واتساب على هاتف فعلي وعلى الكمبيوتر، وعطّل حاجب النوافذ للروابط عند الحاجة. حدّد نطاق الموقع في `metadataBase` عند معرفة الدومين النهائي لضبط روابط المعاينة الاجتماعية. أضف المشروع إلى GitHub أو ارفع الناتج إلى مزوّد الاستضافة الذي تختاره، ثم نفّذ طلباً تجريبياً واضحاً بالتنسيق مع المطعم.
